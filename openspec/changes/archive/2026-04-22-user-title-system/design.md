## Context

足跡打卡（luroufan-footprint）記錄了每位用戶的打卡數。稱號系統以打卡的唯一店家數為依據，計算稱號並產生代號，提供升級儀式感。

## Goals / Non-Goals

**Goals:**
- 依打卡唯一店家數計算當前稱號
- 首次達到新稱號門檻時觸發升級事件，大叔給予特別回應
- 自動產生不重複的數字代號（稱號 + 全域流水號）
- 用戶可查詢自己的稱號、代號、距下一級的進度

**Non-Goals:**
- 不支援用戶自訂代號（第一版系統自動產生）
- 不提供稱號排行榜或社群比較
- 不支援降級

## Decisions

### 稱號門檻

| 稱號 | 打卡唯一店家數 |
|------|---------------|
| 無職轉生者 | 0–4 家 |
| 肉汁騎士 | 5–14 家 |
| 滷鍋守護者 | 15–29 家 |
| 魯肉飯勇者 | 30–59 家 |
| 魯肉飯大神 | 60 家以上 |

門檻設計讓用戶在早期（5 家）就能快速升級，維持動力；魯肉飯大神需要真正吃遍大半台北（60 家以上）。

### 代號產生方式

代號格式：`{稱號}#{N}`，N 為 Firestore `title_counter/<title>` 文件的全域遞增整數。

例如：第 47 個升到「肉汁騎士」的用戶代號為「肉汁騎士#47」。

代號一旦產生不再變更。升級時更新稱號並重新產生新稱號的代號（不保留舊稱號代號）。

**理由**：用流水號避免重複，不需要 UUID，代號直觀有收藏感。

### 升級事件偵測

每次打卡完成後，系統重新計算唯一打卡數並對應稱號。若稱號與 Firestore 中儲存的 `current_title` 不同，則觸發升級事件。

升級事件：
1. 從 `title_counter/<new_title>` 取得並遞增流水號
2. 更新 Firestore `user_footprint/<user_id>` 的 `current_title` 和 `title_number`
3. 回覆升級儀式感訊息（獨立一則訊息，在打卡確認之後送出）

### 代號查詢入口

用戶輸入「我的代號」→ 大叔回覆稱號、代號、目前打卡數、距下一級幾家。達人不顯示「距下一級」。

### Firestore 資料

`user_footprint/<user_id>` 文件新增欄位：
- `current_title`: string（"無職轉生者" / "肉汁騎士" / "滷鍋守護者" / "魯肉飯勇者" / "魯肉飯大神"）
- `title_number`: int（代號流水號）

全域計數器：
- `title_counter/肉汁騎士` → `{ count: N }`
- `title_counter/滷鍋守護者` → `{ count: N }`
- `title_counter/魯肉飯勇者` → `{ count: N }`
- `title_counter/魯肉飯大神` → `{ count: N }`

（無職轉生者不需要計數器，代號為「無職轉生者#<user_id後4碼>」）

## Risks / Trade-offs

- **並發升級衝突**：多用戶同時升級可能導致流水號重複 → 使用 Firestore transaction 遞增計數器
- **打卡後計算延遲**：打卡非同步寫入，升級偵測在寫入完成後執行，不影響打卡確認回應時序
